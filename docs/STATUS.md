## Points bloqués / dépendants du pilote

- **Forme réelle de `getPlayerGarageData`** (et des 7 autres réponses du garage) : à lire dans `%LOCALAPPDATA%\Corde\diagnostics\lmu-api\garage\<voiture>\` après un passage au garage avec Corde ouverte. Tant qu'elle n'est pas confirmée, l'extracteur des bornes accepte des formes supposées et Corde limite toute hausse à +2 crans (« maximum inconnu »). À vérifier aussi chez le pilote : le chargement d'un `Corde_….svm` dans le garage (rafraîchir la liste), les libellés réécrits par le jeu, le choix automatique de la base sur ses sessions.

- **Validation de l'application de bureau** : le pilote installe `Corde_…_x64-setup.exe` depuis la pré-release `continuous` et rapporte ce qui cloche (journal : `%LOCALAPPDATA%\Corde\logs\corde-desktop.log`). Hypothèses LMU restantes : `TODO(verify-on-pc)` dans `crates/corde-lmu/src/*.rs`.
- **Base du pilote** : les sessions enregistrées par l'alpha 1 se corrigent avec `corde-store reconcile` (rapprochement avec les fichiers de résultats du jeu) — fait sur une copie, à appliquer chez lui.
- **Passage en open source** (décision du propriétaire, 11 nov.) : plan dans `docs/adr/0008-open-source-publication.md`. **Décidé** : licence GPL-3.0-or-later (fait : `LICENSE`, champs `license`, README), nom Corde, dépôt public `dultra123/corde`. **En attente du propriétaire** : créer le dépôt public neuf `dultra123/corde` (le dépôt actuel reste une archive privée) et y donner accès à l'agent. **Ne pas passer le dépôt actuel en public** : 16 des 26 commits portent une adresse e-mail privée et d'anciennes versions des échantillons, de tests et d'une capture contiennent les vrais noms des pilotes d'une course en ligne ; la référence de la PR n° 1 et les branches les garderaient visibles même après réécriture. L'arbre courant, lui, est propre (contrôle du 11 nov. : dépendances toutes permissives, aucun code tiers, aucun nom réel). Une fois public : demander la signature gratuite (SignPath Foundation, ADR 0007).
- **Sécurité avant publication** (lot du 11 nov.) : serveur local durci — contrôle des en-têtes `Host` (DNS rebinding) et `Origin` (`/api/*` et WebSocket, 403 même en lecture), CORS limité aux origines locales et à la même origine, suppressions / recalcul / réimport / fichiers de réglage / réglages réservés au PC, corps ≤ 1 Mio, détails des 5xx masqués au réseau (`crates/corde-server/src/guard.rs`, tests `tests/access_policy.rs`). Modèle et tableau des routes : `docs/SECURITY-MODEL.md`. Fichiers publics : `SECURITY.md`, `PRIVACY.md`, modèles de ticket et de PR, `deny.toml` + job CI `deny` (informatif). CI : publication limitée aux poussées de `dultra123/corde`, secrets de signature jamais donnés à une PR. Avis connu : RUSTSEC-2026-0459 (SQLite embarqué par rusqlite 0.40) ignoré avec justification dans `deny.toml` — passer à rusqlite 0.41 demande Rust 1.89 (workspace : 1.85).
- **Dépôt** : le dépôt de développement (privé) a changé d'adresse le 11 nov. au soir (compte renommé ou transfert) ; il devient l'archive privée. Le dépôt public sera `dultra123/corde` (liens du README, de `Cargo.toml`, du guide d'installation et de la CI déjà à jour). Tant qu'il n'existe pas, la réussite de la CI se constate par le déplacement de l'étiquette `continuous` (`git ls-remote origin refs/tags/continuous`). **Prochaine session : l'ouvrir sur le dépôt public.**
- **Nom de l'application** : **décidé le 11 nov. : Corde** (le point de corde). Renommage fait en 0.3.0 ; à vérifier chez le pilote : la reprise de ses données au premier lancement (journal `%LOCALAPPDATA%\Corde\logs\corde-desktop.log`, lignes « data folder of the former name… »), puis la désinstallation de l'ancienne application.
- **Signature de code** (SmartScreen, **Smart App Control**) : décision du propriétaire, voir ADR 0007. Le pilote pense que c'est Smart App Control qui a bloqué l'alpha : s'il est sur « Activé », une application non signée est refusée **sans** bouton « Exécuter quand même » (FAQ Microsoft) — la signature (ou le Microsoft Store) devient alors nécessaire, sauf à désactiver SAC sur son PC.
- **Page « Courses »** (demande du 11 nov. : courses en ligne disponibles, inscription, sonnerie 5–10 min avant) : étude en cours. Faits établis : l'inscription aux courses officielles (Daily / Weekly / Special) se fait **dans le jeu** (guide officiel) ; les serveurs démarrent 5 min avant ; cadences Beginner 1 h / Intermediate 2 h / Advanced 3 h ; `racecontrol.gg` liste publiquement les Daily de la semaine (nom, niveau, durée, circuit, sans horaire) et les événements communautaires (horaires, inscription sur le site). Le studio a mis en garde contre les outils tiers qui sollicitent ses serveurs : ne rien interroger d'autre que le jeu local et les pages publiques, à faible fréquence. **Prochaine donnée nécessaire** : la description de l'API locale du jeu — `corde-server::lmu_api` en garde désormais une copie dans `<données>/diagnostics/lmu-api/` (un GET en lecture seule de `/swagger-schema.json` quand le jeu est détecté ; `--no-game-api` pour le couper).
- **Releases numérotées** : les tags `v*` ne peuvent pas être créés depuis la session d'agent ; la pré-release `continuous` (créée par la CI elle-même) les remplace pour l'instant.
- **Décisions ouvertes** : signature de code (ADR 0007). Tranchées le 11 nov. : nom (Corde), licence (GPL-3.0-or-later), destination (open source, ADR 0008).

## Commandes utiles

```bash
cargo test --workspace                      # tests Rust (layouts mémoire inclus)
cargo run -p corde-server -- --source sim    # serveur en mode démo sur :8471 (enregistre dans ~/.local/share/corde)
cargo run -p corde-server -- --source sim --sim-track-length 1500 --sim-lap-time 30 --sim-speed 3 --record-rate 20   # tours de 10 s pour tester l'enregistrement
cargo run -p corde-store -- sessions list    # sessions enregistrées (show <id>, export-csv <id> <tour>, stats)
curl -s http://127.0.0.1:8471/api/sessions/<id>/analysis | jq .summary_fr   # rapport de l'ingénieur (cache ; POST …/analysis/recompute pour forcer)
cargo run -p corde-server -- --source sim --lmu-results-dir reference/samples   # profil alimenté par les deux fichiers XML réels (http://127.0.0.1:8471/#/profile)
pnpm --filter @corde/ui dev                  # UI en dev (proxy vers :8471) — http://localhost:5173/#/sessions pour le navigateur de sessions
pnpm --filter @corde/ui build                # UI de prod dans packages/ui/dist
node packages/ui/scripts/screenshot-sessions.mjs --spawn   # captures des pages Sessions + Profil (lance le serveur sim lui-même, ~1 min)
node packages/ui/scripts/screenshot-sessions.mjs --spawn --profile-only   # seulement profile.png / result.png / profile-mobile.png (~10 s)
node packages/ui/scripts/screenshot-sessions.mjs --spawn --engineer-only  # engineer.png / engineer-full.png / engineer-mobile.png (~1 min : 3 tours propres)
curl -s -X POST -H 'Content-Type: application/json' -d '{"plan":"safe","text":"instable au freinage"}' http://127.0.0.1:8471/api/sessions/<id>/feedback   # ressenti → {feedback, interpretation, iteration} (GET pour la liste)
curl -s http://127.0.0.1:8471/api/sessions/<id>/iterations?plan=safe | jq '.[-1].delta'   # dernière itération du plan sûr
cargo run -p corde-server -- --source sim --game-user-data <dossier UserData>   # réglages .svm lus dans <dossier>/player/Settings (sans le jeu)
curl -s "http://127.0.0.1:8471/api/setups?session=<id>" | jq '.proposed'        # base proposée pour la session
curl -s "http://127.0.0.1:8471/api/sessions/<id>/setup-preview?plan=safe" | jq '.file_name, .changes[].resolved.values'   # plan résolu, rien d'écrit
```
